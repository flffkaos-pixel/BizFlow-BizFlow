# Dify 채팅봇 앱 설정 가이드

이 문서는 n8n 워크플로우(`kakao-booking.json`)와 연결되는 Dify 챗봇 앱을 만드는 방법입니다.
Dify가 분석한 결과에 따라 **`[예약]` 이 태그가 붙으면 n8n이 Cal.com 예약을 만들고, 아니면 일반 답변을 그대로 돌려줍니다.**

---

## 1. Dify 앱 만들기

1. Oracle 서버의 Dify 접속: `https://dify.내도메인.com`
2. 왼쪽 메뉴 **"앱 만들기"** 클릭
3. **"챗봇"** 유형 선택 → 이름 **"상담챗봇"** 입력 → 만들기

## 2. 대화 앱 유형 확인

만든 앱이 **"대화 앱 (Chatflow)"** 인지 확인하세요.
대화 앱이라면 아래 단계가 그대로 적용됩니다. (워크플로우 앱이면 3번부터 동일하게 적용 가능)

## 3. 시스템 프롬프트 입력

**"프롬프트 엔지니어"** 모드 또는 **"오케스트레이션"** 탭에서 시스템 프롬프트에 다음을 붙여넣기:

```
당신은 중소기업 AI 상담 비서입니다. 사장님(오너) 대신 고객 문의에 답변합니다.

## 역할
- 한국어로 답변하며, 친절하고 간결하게 답변합니다.
- 예약 관련 문의를 가장 먼저 탐지하세요.

## 예약 판단 규칙 (가장 중요)
고객이 다음 의도 중 하나라도 보이면 반드시 예약 정보를 파악하세요:
- 상담/방문/견적 예약
- 언제 가능한지 묻는 경우 (날짜/시간 문의)
- 예약하고 싶다 / 상담받고 싶다

예약을 파악하면 응답 맨 앞에 반드시 아래 형식으로 메타데이터를 붙이세요:
```
[예약]
고객명: {고객명}
이메일: {이메일 또는 unknown@example.com}
시작일시: {YYYY-MM-DDTHH:mm:ss}
행사타입ID: {이벤트 타입 ID}
메모: {간단한 메모}
```

## 규칙
- 고객이 예약 의사를 보이면 날짜와 시간을 물어보세요. 특정일을 못 정하면 2~3개 후보를 제안하세요.
- 예약 확정 정보를 받으면 위 형식으로 메타데이터를 붙여 응답하세요.
- 예약이 아닌 일반 문의는 메타데이터 없이 자연스럽게 답변하세요.
- 영업시간은 평일 09:00~18:00, 주말 휴무입니다.
```

> ⚠️ n8n은 응답에 `[예약]` 이 포함된 경우에만 Cal.com 예약을 만듭니다. 프롬프트를 지우면 안 됩니다.

## 4. 예약이 필요한 3개 변수

워크플로우가 Cal.com에 전달하는 값 3개를 반드시 Dify 응답에서 채워야 합니다.

| 변수 | 내용 | 예시 |
|------|------|------|
| `고객명` | 고객 이름 | 홍길동 |
| `이메일` | 고객 이메일 | hong@example.com |
| `시작일시` | 예약 시작 시각 (ISO 8601) | 2026-08-10T14:00:00 |

`행사타입ID` 는 Cal.com에서 직접 얻은 값(아래 가이드 2번 참고)을 Dify 프롬프트에 하드코딩하세요.

## 5. LLM 모델 설정

- 모델: 셀프호스트로 돌리면 무료 모델을 넣을 수 있습니다 (예: Ollama + llama3).
- 또는 OpenAI/Gemini API 키가 있다면 그걸 사용.
- 비용 절감을 위해 `gpt-4o-mini` 같은 저가 모델 권장.

## 6. Dify API 키 발급

1. 화면 오른쪽 위 **"API 액세스"** 클릭
2. **"API 키 생성"** 클릭 → 키 복사
3. `oracle/.env`의 `DIFY_API_KEY=` 에 붙여넣기

## 7. 공개 URL 설정

Dify 앱의 **"API 액세스"** 화면에서 API Base URL을 확인하세요.
기본값: `https://dify.내도메인.com/v1` — n8n 워크플로우가 이 URL로 요청합니다.
만약 포트가 붙은 URL이라면 n8n 워크플로우의 `dify-analyze` 노드 URL을 그에 맞게 수정하세요.

## 8. 테스트

Dify 화면에서 직접 채팅으로 테스트:

```
안녕하세요, 다음주 화요일 2시에 상담 예약하고 싶어요.
```

- 위 프롬프트 형식의 `[예약]` 메타데이터 응답이 오는지 확인
- 안 오면 시스템 프롬프트를 다시 확인하거나, "오케스트레이션 > 추가 지시" 에 재작성

## 9. (선택) 보안

- Dify API 키가 노출되지 않도록 **서버 내에서만 호출** (n8n이 서버 안에 있으므로 기본적으로 안전)
- Dify 앱을 외부에 노출하는 도메인은 Cloudflare Tunnel 경유로 감싸기 (이미 oracle/docker-compose.yml에 구성됨)
